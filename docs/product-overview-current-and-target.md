# AI Novel Studio 产品说明文档

## 1. 产品定位

AI Novel Studio 是一个面向长篇小说创作的 AI 辅助生产系统。

它的目标不是只生成一段正文，而是帮助作者完成从创意、设定、大纲、章节正文、连续性维护、质量检查到导出的完整长篇小说生产流程。

目标用户包括：

- 长篇网文作者
- 工作室型内容团队
- IP 孵化团队
- 希望用 AI 辅助完成中长篇故事生产的个人创作者

产品核心价值：

- 降低长篇小说从 0 到 1 的启动成本
- 提升章节连续生成效率
- 维护人物、世界观、伏笔、状态和剧情线的一致性
- 支持批量生成、修改、回滚和导出
- 将“单次 AI 对话”升级为“可管理的小说生产线”

## 2. 目标产品形态

最终目标是做成一个企业级长篇小说生成与管理平台。

理想形态下，用户可以：

1. 创建作品，填写题材、目标字数、平台风格和创作方向。
2. 生成多个创意方案，并选择一个进入后续流程。
3. 生成结构化设定库，包括人物、组织、地点、物品、世界规则。
4. 生成人工可编辑、可确认的全局大纲。
5. 按卷、剧情单元、章节逐步扩展长篇大纲。
6. 一次性创建 10、20、50 章正文生成任务。
7. 系统按章节顺序串行生成正文，并自动维护上一章到下一章的连续性。
8. 每章生成后自动抽取事实、更新人物状态、关系、事件、伏笔和记忆。
9. 用户可以查看当前世界状态、活跃伏笔、脏数据范围和重建结果。
10. 系统能检查人设冲突、剧情重复、伏笔遗漏、节奏问题和大纲偏离。
11. 支持版本管理、恢复旧版本、从某章开始重算后续状态。
12. 支持 Markdown、TXT、DOCX、PDF 等格式导出。
13. 支持多模型配置、成本统计、任务审计和团队协作。

简化成一句话：

> 目标产品是一个“长篇小说生产工作台”，而不是一个“章节文本生成按钮”。

## 3. 当前已经形成的主流程

目前系统已经具备初期闭环：

```text
创建作品
-> 生成创意
-> 生成/确认设定库
-> 生成/确认大纲
-> 生成章节大纲
-> 生成章节正文
-> 后处理章节事实和记忆
-> 检查
-> 导出
```

当前已经可以完成一个简单作品从构思到章节正文再到导出的基础流程。

## 4. 当前已实现功能

### 4.1 作品管理

已支持：

- 创建作品
- 维护作品标题、题材、目标字数、单章目标字数
- 设置平台目标和风格偏好
- 根据作品状态进入不同创作阶段

当前价值：

- 为后续创意、设定、大纲和章节生成提供统一项目上下文。

### 4.2 创意生成

已支持：

- 根据作品方向生成多个创意方案
- 选择创意进入后续流程
- 记录创意版本

当前价值：

- 帮助作者快速找到故事卖点、世界观方向和主线冲突。

### 4.3 设定库

已支持：

- 设定库生成与确认
- 结构化维护：
  - 人物
  - 组织
  - 地点
  - 物品
  - 世界规则
  - 事件
  - 实体关系
  - 状态记录
- 设定快照查询
- Redis 缓存部分稳定上下文

当前价值：

- 不再只依赖一段设定文本，而是开始把世界观拆成可维护的数据。

### 4.4 大纲工作流

已支持：

- 生成大纲草案
- 检查大纲草案
- 提交大纲草案
- 写入全局大纲、分卷、剧情单元和首批章节大纲
- 继续生成章节大纲接口

当前价值：

- 已经从“只有全局大纲”推进到“全局大纲 + 卷 + 剧情单元 + 章节大纲”的分层结构。

当前注意点：

- 旧的覆盖式章节大纲生成接口曾经会删除已有章节并写入 mock 大纲。
- 现在已经加了保护：已有章节时不允许再走覆盖式生成，应使用“继续生成章节大纲”。

### 4.5 章节正文生成

已支持：

- 单章正文生成
- 单章正文重写
- 后端 Flux 流式输出
- 前端实时显示流式正文
- 生成完成后记录版本和任务

当前价值：

- 用户点击生成正文后，可以看到内容逐步输出，而不是长时间无反馈。

### 4.6 同项目章节串行队列

已支持：

- 同一个作品内，流式章节生成串行执行
- 后一章等待前一章完成
- 等待中的任务返回 queued 状态
- 正文生成后进入 post_processing 状态
- 队列等章节后处理完成后才释放下一章
- 不同作品之间可以并行

当前价值：

- 保证第 N+1 章不会在第 N 章摘要、事实、记忆尚未更新时提前生成。
- 这是长篇连续性的重要基础。

### 4.7 章节后处理

已支持：

- 章节摘要生成
- 章节事实抽取
- 事件投影
- 人物/实体状态投影
- 实体关系投影
- 伏笔线程更新
- 近期记忆、中层记忆、高层记忆、全局记忆更新
- 下游脏数据标记
- 从指定章节重建部分状态

当前价值：

- 系统已经不只是保存正文，而是开始理解“这一章发生了什么”。
- 后续章节可以基于事实、状态、伏笔和记忆生成，而不是只靠上一章文本。

### 4.8 Redis 缓存

已支持：

- 引入 Redis 依赖和缓存配置
- 缓存部分章节上下文稳定数据
- 在设定、大纲、记忆等变更时做缓存失效

当前价值：

- 减少每次生成章节时重复查询稳定上下文。
- 为后续多任务生成和高频上下文读取做准备。

### 4.9 导出

已支持：

- Markdown 导出
- TXT 导出
- 浏览器直接下载
- 记录导出版本快照

当前价值：

- 用户可以把阶段性成果拿出系统使用。

## 5. 当前系统的核心亮点

### 5.1 已经不是简单 Prompt 拼接工具

系统已经有结构化设定、结构化大纲、章节记忆、事实抽取和状态投影。

这意味着它具备向长篇一致性系统演进的基础。

### 5.2 章节后处理方向正确

每章生成后做摘要、事实、状态、伏笔、记忆更新，这是长篇小说系统必须具备的能力。

这个方向比“把所有历史正文都塞进 prompt”更可持续。

### 5.3 同项目串行队列是正确架构

小说正文不是普通批处理文本。第 2 章依赖第 1 章，第 3 章依赖第 2 章。

同项目串行、不同项目并行，是当前阶段合理的调度模型。

### 5.4 已经开始具备版本意识

正文、摘要、大纲、导出等都有版本记录。

这为后续恢复、回滚、对比和审计打基础。

## 6. 当前主要问题

### 6.1 批量任务系统还不完整

现在有单章队列，但还没有真正的持久化批量任务。

如果用户要一次生成 50 章，当前还缺：

- 批量任务记录
- 子任务状态
- 进度查询
- 失败重试
- 暂停/取消
- 服务重启后恢复

### 6.2 章节大纲续写还需要产品化

虽然已经有继续生成章节大纲接口，但还需要完善：

- 大纲页交互
- 生成前预览范围
- 批次拆分
- 质量检查
- 失败恢复
- 不覆盖已有内容的强保护

### 6.3 前端对长篇状态的展示不足

后端已经有不少结构化数据，但前端还没有充分展示：

- 当前人物状态
- 事件时间线
- 实体关系变化
- 活跃伏笔
- 脏数据范围
- 重建结果
- 章节连续性警告

### 6.4 质量检查能力还弱

当前检查还没有形成完整闭环。

企业版需要：

- 大纲偏离检查
- 人物状态冲突检查
- 伏笔遗漏检查
- 重复桥段检查
- 节奏检查
- 爽点密度检查
- 章节目标完成度检查

### 6.5 多实例部署能力不足

当前队列是单机内存队列。

如果后端部署多个实例，同一个项目的请求可能落到不同实例，需要升级为：

- Redis 分布式锁
- Redis Stream
- 数据库任务抢占
- 或消息队列

## 7. 下一阶段产品目标

下一阶段建议目标：

> 从“单章生成工作台”升级为“长篇批量生产工作流”。

优先做两个功能：

1. 继续生成章节大纲
2. 批量生成章节正文

## 8. 下一阶段功能设计

### 8.1 继续生成章节大纲

用户目标：

- 已经有 10 章大纲后，继续生成第 11-20 章。
- 已经有 50 章大纲后，继续生成第 51-100 章。
- 不覆盖已有章节。

推荐能力：

- 选择追加数量：10 / 20 / 50
- 填写补充要求
- 根据当前最大 chapterNo 自动续写
- 内部按 10 章一批调用模型
- 失败时保留已成功批次
- 插入新章节，不删除旧章节

### 8.2 批量生成章节正文

用户目标：

- 选择从第几章开始
- 一次生成 10、20、50 章正文
- 后台按顺序执行
- 前端查看进度
- 中途失败可重试

推荐能力：

- 创建批量任务
- 后台 worker 串行处理章节
- 每章生成后完成后处理
- 记录每章状态
- 支持暂停、取消、重试失败项

建议新增表：

- generation_batches
- generation_batch_items

## 9. 企业版目标能力清单

### 9.1 任务中心

统一管理：

- 大纲续写任务
- 正文批量生成任务

- 质量检查任务
- 导出任务

### 9.2 长篇一致性中心

- 物品归属
- 事件时间线
- 未解决冲突
- 活跃伏笔

### 9.3 质量控制中心

- 单章检查

- 人物一致性检查

### 9.4 版本和恢复

## 10. 当前建议开发路线

### Phase 1：稳定已有闭环

目标：

- 防止旧接口覆盖已有章节
- 修复乱码文案
- 修复前端状态误清空
- 确认恢复机制可用

### Phase 2：继续生成章节大纲

目标：

- 产品化追加式大纲生成
- 完善前端交互
- 增加范围预览和保护提示
- 支持 10 / 20 / 50 章追加

### Phase 3：批量生成正文

目标：

- 新增批量任务
- 后台串行生成
- 前端进度展示
- 支持失败重试

### Phase 4：质量检查和重建

目标：

- 检查长篇一致性
- 暴露脏数据和重建能力
- 支持从第 N 章开始重算

### Phase 5：企业化能力

目标：

- 多用户
- 权限
- 审计
- 成本统计
- 任务中心
- 多格式导出

## 11. 当前产品一句话总结

AI Novel Studio 当前已经完成了长篇小说生成系统的早期闭环，具备创意、设定、大纲、章节正文、章节后处理、记忆、事实投影和导出的基础能力。

下一阶段的关键不是继续堆单点生成按钮，而是建设长篇生产线所需的任务系统、大纲续写、批量正文生成、连续性检查和版本恢复能力。
